표현 위계와 의미 위계

표현과 의미를 각각 줄 세우고 둘을 잇는다. 두 줄은 서로 다른 자로 잰다 — 표현은 식별력(먼저 눈에 갈리는 순서), 의미는 사용빈도(자주 쓰는 순서). 그래서 「의미가 아래라고 표현도 아래」가 아니다. Version B 에서 매핑의 둘째 축은 곡률이 아니라 양 끝 노드의 조합이고, 곡선은 edge 에서 쓰지 않는다.

이 페이지는 보조판이다. 시각 정본은 사용자가 만든 규격 시트 「도식 표기 규격 B」(10 plate)이고, 둘이 어긋나면 그쪽이 이긴다 — 실제로 이 페이지가 한 자리에서 어긋나 있었다(겹침 해결의 채움 배정이 반대였다. 2026-09-13 수리).

표현 위계 — 식별력 순서

같은 것을 여러 방식으로 그릴 수 있으므로, 먼저 갈리는 것부터 의미를 싣는다. 아래가 그 순서다.

의미 위계 — 사용빈도 순서

의미의 줄은 식별력이 아니라 얼마나 자주 쓰는가로 정한다.

순위의미무엇인가위상
1execution_flowProcess(Task · Action · Module · Pipeline · Function)와 Entity(data · relation)의 앞뒤 관계. 가장 기본DAG + cycles
2whole_part
(실행흐름 안)		실행흐름 안에서 메타 수식어로 작동. 추상화 자체가 이 구조다 — 상단을 남기고 하단을 은닉tree 기본 · DAG 가능
3goal_means수단 → 목적. 필수성·필요성 판단에 쓴다DAG
4is_a상위·하위개념 chain. 문장 속 낱말의 뜻을 이해하려 할 때 쓴다tree 기본 · DAG(다중 상속)

Process 를 실제로는 Task 라 부른다 — 비개발자의 이해가 쉬워서다. 더 구체화할 때만 Action 을 쓴다.

매핑 — Version B: 노드 조합이 의미를 정한다

표현의 수가 유한하므로, 선의 모양을 늘리는 대신 양 끝에 무엇이 있는가를 읽는다.

겹침과 확실성

전체/부분은 곧 추상화다 — semantic zoom

영역의 실/점은 확실성이 아니라 층을 말한다: 실선 = 현재 Focus View, 점선 = 상위 그룹. 한 단계 올리면 셋이 한 칸씩 밀린다 — 실선의 내용은 은닉되고, 점선이 실선이 되며, 그 위가 새 점선이 된다.

아직 미결

  • Core / Main / Sub 라는 이름을 없앨 것인가. 정본이 제기했다 — 이름 대신 우선순위를 전부 명시하는 안. 이 페이지는 아직 순위로만 쓰고 이름을 쓰지 않는다.
  • whole_part 에 확실성이 적용되는가(정본 §4 의 ?). 영역의 실/점이 이미 층을 나르므로 자리 다툼이 있다.
  • 구현/구현체 관계를 별도 의미로 둘지, goal_means 에 넣을지.
  • 색 5색의 배정. 축은 확정됐지만 어느 색이 무엇을 뜻하는지는 아직 비어 있다.
