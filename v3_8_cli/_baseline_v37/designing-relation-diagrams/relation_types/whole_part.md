# whole_part — 부분과 전체

추상화와 직결된다. 상위 단계는 tree의 윗부분을 남기고 아랫부분을 접어 만든다.

## 모양과 의미

| 요소 | 모양 | 비고 |
|------|------|------|
| 전체 (펼침) | 포함 영역 | 전체 node에 `"drawRegion": true` |
| 전체 (접힘) | 전체 node 자신의 `role` 모양 + [+] | 접혀도 모양이 바뀌지 않는다 |
| 부분 | 영역 안의 node | `"parent": 전체 id` |

- execution_flow 안에서는 흐름의 일부 단계를 묶는 수식어로 쓰인다(예: "결제는 카드 인증과 승인 요청으로 이루어진다").
- **읽는 법**: "X는 Y의 부분이다"로 읽는다. 포함(X가 Y 안에 들어 있다)이나 집합 기호(⊃)로 읽지 않는다. 부분은 "어떤 X들이 모여 Y를 이룬다"는 뜻이며, 모든 X가 Y의 부분이라는 뜻이 아니다.
- **is_a와의 경계**: 정의(상위개념 + 종차)가 먼저 있고 그 정의로 관계가 성립하면 is_a다. 구성이나 데이터를 보고 해석해 부분을 나누고 그다음에 이름을 붙였다면 whole_part다.
- **세는 대상**: 부분을 셀 때 세는 것은 구성원(데이터의 index나 인코딩 값)이다. 부분에 붙인 이름은 그 구성원 묶음에 덧붙인 설명 label이므로, node에서 세는 대상과 설명을 구분해 적는다.
- **겹침**: 부분끼리 겹칠 수 있다. 겹치면 부분의 합이 전체와 같다고 가정하지 않는다.
- **묶음은 요청에 명시된 것만** 만든다. 이름이나 성격이 비슷해 보여 묶는 것은 묶음 기준을 고르는 일이므로, Human에게 후보를 제시해 고르게 한다([common.md](../common.md) §4).

## 확실성

| 상태 | 영역 경계 |
|------|-----------|
| 묶음 결정 | 실선 (기본) |
| 묶음 미정 | 짧은 점 `2 6` (`"certainty": "dashed"`). 정도는 두지 않는다 |

## 접기와 펼치기

- `expandAt`: 이 L 단계부터 펼친다. `--level`로 L0–L2를 바꿔 같은 IR을 다시 그린다.
- 그룹을 하나씩 펼치는 화면은 `--expand grp_id`로 만든다. 한 [+]를 누르면 그 그룹만 펼쳐지게 한다.
- 접힌 node로 가던 edge는 가장 가까운 보이는 전체 node로 올라가고, 중복·자기 edge는 지워진다.

## 위상

- 기본은 tree다. 부분은 같은데 전체가 다른 경우(다중 전체)는 DAG가 될 수 있다.
