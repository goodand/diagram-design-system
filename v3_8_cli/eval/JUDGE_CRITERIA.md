# JUDGE_CRITERIA — GC-1 · GC-3 · GC-4 결과 판정 기준

- 작성: 평가 설계자(독립). skill 본문, `_baseline_v37/`, SPEC_cli.md, REWRITE_MAP.md, decisions/, eval/runs/ 는 **열지 않았다**.
- 읽은 입력: `eval/gc_tasks_human_rewrite.json`, `eval/prereg/GC-{1,3,4}.json`, `../../digram_design.md`(전문).
- 목표(Human 결정, 「완료는 결과로 판정」): 맞는 도식이란 **(G1)** design system 규칙대로 그려졌고, **(G2)** Human 이 정해야 할 것은 Human 이 정했으며(agent 가 말없이 정하지 않음), **(G3)** 실제로 보여 준 그림이 agent 가 선언·결정한 것과 같다.
- 판정은 **Human 이 받은 결과**만 본다. 어떤 버전이 어떤 내부 명령·파일(IR, check 스크립트 등)을 썼는지는 판정에 넣지 않는다.

## 0. 공통 정의

| 용어 | 정의 (결정적) |
|---|---|
| 증거 E1 | transcript(stream-json): assistant 메시지, tool 호출 입력, tool 결과, 순서(index) |
| 증거 E2 | 모의 Human 답(prereg 답 + 분류기 기록: 질문 index, 선택된 topic, 반환한 답) |
| 증거 E3 | 최종 작업 폴더의 모든 파일(이미지·SVG·HTML·JSON·md) |
| 최종 그림 F | ① 마지막 assistant 메시지가 Human 에게 가리킨 렌더 가능 파일(.svg/.html/.png). ② 가리킨 파일이 없으면 과제가 요구한 형식의 파일 중 mtime 최신. ③ 내용이 다른 후보가 둘 이상이고 ①로 가려지지 않으면 HOLD `H-AMBIG` |
| 보여 준 그림 S_k | assistant 메시지 k 가 경로·첨부·인라인으로 제시한 렌더 파일 중, 그 시점(E1 index)에 이미 써져 있던 것. 그 뒤에 Human 답이 오면 「Human 에게 보여 줌」 |
| 그림 추출 X(F) | headless 브라우저(Chromium)로 F 를 열어 DOM/계산 스타일에서 뽑는다: 텍스트 라벨, 도형(텍스트 bbox 를 담는 가장 작은 도형 = 그 라벨의 노드), 간선(line/path/polyline, 양 끝에서 가장 가까운 노드 bbox), 화살촉(marker-end 또는 끝점 12px 안 삼각 polygon), dasharray, fill, stroke 색, path 의 C/Q/S/A 명령(곡선). 범례는 「범례/legend」 텍스트를 가진 컨테이너 안을 제외 |
| stadium | 도형 모서리 반경 r ≥ 0.45 × 높이 (SVG rx, HTML computed border-radius). 그 외 rect(작은 r 은 둥근 rect = rect) |
| region | 노드 도형 ≥2 개를 bbox 로 둘러싸는 도형. 텍스트는 자기 라벨 하나뿐 |
| 라벨 일치 | 공백·구두점 제거 후 완전 일치. 불일치 라벨은 LLM 슬롯 `alias(요청어, 그림 라벨)∈{same,different}` 을 독립 2회 채움 → 둘 다 same 일 때만 일치, 불일치 시 HOLD `H-SLOT` |
| 5색 | 흑(전경)·백(배경)·빨·초·파. 무채색(채도 <0.15)은 흑/백 및 그 흐림(s-faint/n-faint)으로 허용. 유채색은 색상각 빨 [345°,15°], 초 [90°,150°], 파 [200°,250°] 만 허용 |
| LLM 슬롯 규약 | LLM 은 **슬롯만 채운다**(목록·인용·분류). 판정은 규칙이 한다. 모든 슬롯은 독립 2회, 불일치 시 HOLD `H-SLOT`. 슬롯 출력에 인용이 있으면 규칙이 그 인용이 증거에 실재하는지 문자열로 확인한다 |

### HOLD 사유 코드
`H-AMBIG`(최종 그림 후보 모호) · `H-RENDER`(렌더 실패: 브라우저 오류·빈 DOM 아닌 기술적 실패) · `H-SLOT`(LLM 슬롯 2회 불일치) · `H-PROXY`(모의 Human 이 분류 불가 질문에 기본값으로 답했거나 6턴 상한 도달 — 실행 타당성 의심) · `H-NOEVID`(transcript 결손) · `H-EXTRACT`(라벨은 있으나 노드/간선 귀속 불가). (`H-NOSRC` 는 2026-10-06 삭제: 원천 ↔ 그림 비교 판정이 없어져(DEC-146) HOLD 할 판정이 남지 않음. 원천을 확정할 수 없는 경우는 아래 원천 기록 RS 의 (a) 에 「확정 불가」 사실로 남긴다.) · `H-LLM`(LLM 슬롯 호출 자체 실패 — 사용 한도·시간 초과 등 기반 장애. 2026-10-04 Main 세션 보완: 한도 초과 중 자가 시험에서 호출 실패가 `H-SLOT`으로 잘못 기록됨, 판정 규칙 변경 아님).

(a) 원천 존재: 없으면 「존재하지 않음」만, 있으면 관련 파일명 또는 디렉터리명(과제 요청문뿐이면 「과제 요청문」, 증거에 없는 첨부를 가리키면 「확정 불가: <요청문이 가리킨 이름>」). 경로는 기록일 뿐 판정 근거가 아니다(DEC-139·147). (c) 그림의 그 요소에 `2 6` 점선이 있는가(결정적, X(F)).
- **J8 (c) 개정 (2026-10-06, 하네스 발견 (4))**: (c) 의 「최종 메시지가 그 항목을 Agent 결정·Human 검토 대기로 밝힘」은 정규식으로 찾지 않는다. `deviations` 항목(묶음 X)마다 슬롯 `review_notice(최종 글, X)∈{yes,no}` 를 독립 2회 채운다: 「이 글이 Human 에게, 묶음 X 는 Agent 가 만들었고 Human 이 아직 검토하지 않아 검토를 기다린다는 것을 알리는가」. yes 이면 근거 인용 필수, 규칙이 인용이 최종 글에 실재하는지 문자열로 확인(없으면 no 로 취급). 규칙: 두 채움 모두 yes → (c) 충족. 둘 다 no → (c) 불충족. 갈림 → HOLD `H-SLOT`. Human 답 이전 S_k 의 통보도 그 S_k 를 보인 메시지에 같은 슬롯을 쓴다. 특정 낱말(「검토 대기」「Agent 결정」 등)의 유무는 판정에 쓰지 않는다.
- J10 보완 (2026-10-04, Main 세션 지시: J7=DEC-113, J10=DEC-109, J2·J11=실데이터 결함): Human 결정이 필요 없었으면(Human 이 정해야 할 J8 구조 결정이 없고 agent 의 결정 질문도 없음) NA 이다(Human 결정 DEC-109).
- J11 보완 (2026-10-04, Main 세션 지시: J7=DEC-113, J10=DEC-109, J2·J11=실데이터 결함): 두 claims 채움을 주장별 정규화 집합으로 비교하고, 한쪽에만 있는 주장에 대해서만 H-SLOT 을 내며 그 주장이 판정을 바꿀 때에 한해 항목을 HOLD 한다.

**집계**: V0 PASS 이고 J1–J13 전부 PASS(경고 허용)이면 런 PASS. FAIL 하나라도 → 런 FAIL. 그 외 → 런 HOLD(사유 코드 나열). 버전 비교는 과제×버전마다 N≥5 런의 PASS 비율과 항목별 FAIL 분포로 한다.

**판정에서 뺀 것(별도 보고 A1)**: output_manifest 의 `{id}_ir.json`·`{id}_check.txt`·`node scripts/render_svg.mjs` 등은 특정 스크립트·파일명을 전제하므로 버전 중립이 아니다. 존재 여부는 A1 로 기록만 하고 판정에 넣지 않는다. 단 「만들 수 없는 파일은 notes 에 이유」 위반은 A1 에 표시.

## 2. 과제별 기대 사실 (요청문 + design system 에서만 유도)

### GC-1 (형식 자유)
- 의미: execution_flow + 그 안의 whole_part(「결제는 카드 인증과 승인 요청 두 단계로 이루어져」 = 전체⊃부분, 요청이 명시).
- 필수 라벨(7): 주문, 재고 확인, 결제, 카드 인증, 승인 요청, 배송 요청, 배송 완료 알림. 「결제」는 노드 또는 region 라벨 어느 쪽이든 된다.
- 필수 간선: 주문→재고 확인→결제(영역 진입)→배송 요청→배송 완료 알림; 결제 안에서 카드 인증→승인 요청. 결제가 region 이면 재고 확인→카드 인증, 승인 요청→배송 요청 로도 충족.
- 역할: P = 재고 확인, 카드 인증, 승인 요청, 배송 요청. E = 주문. P/E 모호 = 결제(region 이면 노드 아님), 배송 완료 알림.
- 노드 수 범위(region 제외): 6–12. 12 초과는 J8 ④(추가 노드) 슬롯에서 반드시 점검.
- Human 이 정해야 할 것: **없음**(묶음은 요청이 정함). 따라서 결제 묶음을 묻는 것은 `W-REDUNDANT`. 실패 갈래(재고 없음·결제 거절 등)를 그리면 J8 ④ 대상 → 질문/위임/미정 표시 필요.
- 최종 그림에 보여야 할 것: 일곱 라벨, 결제 region(**실선** 테두리 — 요청이 정한 묶음, DEC-007·113) 또는 펼침 가능한 접힘, 단방향 실선+화살촉 흐름, 채움 없음.
- L0: 결제를 하나로 접은 5단계 흐름이 S_1 의 전형. 노드 수가 F 보다 적어야 한다.

### GC-3 (HTML 필수)
- 의미: execution_flow. 12 소스 → 수집 (N:1 수렴) → 정제 → 적재 → 대시보드.
- 필수 라벨(16): 주문 DB, 회원 DB, 재고 DB, 결제 로그, 배송 로그, CRM, 고객센터 티켓, 앱 로그, 웹 로그, 광고 API, 날씨 API, 환율 API, 수집, 정제, 적재, 대시보드. 소스 12 개는 묶음/접힘이 Human 결정이면 상호작용으로 드러나도 된다(J2).
- 필수 간선: 각 소스(또는 Human 이 정한 소스 묶음)→수집, 수집→정제→적재→대시보드. 소스 사이 간선 없음.
- 역할: E = 12 소스. P = 수집, 정제, 적재. P/E 모호 = 대시보드.
- 노드 수 범위: 묶지 않으면 16(±대시보드 표기 차이). 묶으면 4(수집~대시보드) + 묶음 수.
- 묶음은 **표현** 문제이므로 기본값은 「먼저 묶고 사후 검토」(DEC-132·133·143). 「분석 값(군집 개수 등)은 분석 전에 묻는다」(DEC-094·095)는 분석·형식 문제라 GC-1·3·4 묶음에 적용하지 않는다. 따라서 Human 답 이전에 묶음을 보여도, 그 메시지·보고가 Agent 결정·검토 대기임을 밝히면 PASS(J8), 확정처럼 통보하면 FAIL.
- Human 이 정해야 할(또는 사후 검토받을) 것: **소스 묶음을 쓰면 그 묶음 기준과 소속**, 소스를 접어 숨기면 그 접기, 여러 장 분할. 요청문은 묶음을 정하지 않았다. 아무것도 묶지·접지 않고 16 개를 다 그리면 Human 결정이 필요 없다(design system 에 노드 수 상한 규칙은 없다).
- 최종 그림에 보여야 할 것: 수렴 구조가 한눈에(12→1), 묶음이 있으면 region(Agent 가 정한 묶음도 **실선**, DEC-133·134; 요청문이 미정을 표현하지 않으므로 `2 6` 은 쓰면 FAIL, DEC-141) + Human 결정이 아닌 묶음은 최종 보고 글에 검토 대기로 밝힘(J8 (c)), HTML 이 브라우저에서 단독으로 열림.

### GC-4 (HTML 필수)
- 의미: execution_flow, 주문에서 갈라지는 두 갈래(분기, 병합 없음).
- 필수 라벨(11): 주문, 결제 승인, 정산, 정산 보고서, 출고, 배송 추적, 배송 완료, 리뷰 요청, 리뷰, 평점 반영, 상품 평점.
- 필수 간선: 주문→결제 승인→정산→정산 보고서; 주문→출고→배송 추적→배송 완료→리뷰 요청→리뷰→평점 반영→상품 평점. 두 갈래 사이 간선 0.
- 역할: P = 결제 승인, 정산, 출고, 배송 추적, 리뷰 요청, 평점 반영. E = 주문, 정산 보고서, 리뷰, 상품 평점. P/E 모호 = 배송 완료.
- 노드 수 범위: 11(접기가 Human 결정이면 그 이하).
- Human 이 정해야 할 것: agent 가 접기·숨김·분할·강조 방식 등으로 **그림 내용을 줄이거나 나누면** 그 선택. 11 개를 다 그대로 그리면 필요한 결정은 없다.
- 최종 그림에 보여야 할 것: 주문에서 두 갈래가 갈라지는 모양, 각 갈래 순서, 상호작용을 선언했다면 실제 작동(J11).
