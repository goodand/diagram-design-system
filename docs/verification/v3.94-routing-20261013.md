# v3.94 optional edge routing

Author: chatgpt_gpt6

Opt in with top-level `edge_routing: "libavoid"` and run CLI finalize. Fixed node
positions are retained. Per-edge shape pins and libavoid-js 0.4.5 route orthogonal
connectors. CLI enumerates fold states (maximum eight fold groups), checks all
routes, and embeds a geometry-keyed cache in presentation HTML. Approved source
JSON and hashes retain their ordinary meaning. The browser needs no WASM or network.
Explicit busX/route values are superseded only in this opt-in mode.

Fail on overlapping segments, node-interior penetration, diagonal segments,
invalid endpoints, non-finite coordinates or missing cache. Edge crossings at a
point, label overlap in arbitrary diagrams, and aesthetic layout are not guaranteed
absent. Label placement chooses the less obstructed side of the longest segment.

Actual supplied core-experiment: collapsed shared path 14 px -> 0; expanded shared
path 45 px -> 0, node intrusion 344 px -> 0. Strict checks include source/target
nodes. Initial free-point endpoints failed and were replaced by shape-attached pins.
Main read final collapsed and expanded screenshots. Final Core HTML folds and
expands all eight nodes without browser errors. Existing 99 tests passed; three new
tests recompute the geometry, reject bad endpoints and reject stale cache.
Prior Full example was regenerated with routing enabled; browser checks passed
for shared/unique Hover, state tokens, cancellation, all-fold and reload-folded.
The reused Function/Core artifacts in that Full browser runner were unchanged.

Workspace evidence: outputs/dds-routing-trial/evidence.json, regression.txt,
