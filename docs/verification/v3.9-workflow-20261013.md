## Implementation

- Actual canonical types: `Function_Definition`, `Process_Summary_Linear`, `Process_Summary_Router`, `Process_Core`, `Process_Full`.
- Exact parent references bind file path, ID, version and SHA-256. `node_id` is the sole process-link key. Nested relative paths resolve from each referencing file. Stale ancestors reject descendants.
- Function is exactly one input, one Process and one output. Summary has 1–3 Processes and global E2E Entities only, without intermediate Entities or visible edge labels. Linear is a chain; Router is an explicitly declared exclusive/parallel DAG with a branch.
- Core adds intermediate data, limits source nodes to nine, and belongs to one Summary Process. Full selects 2–3 approved Cores, covering every Summary Process exactly once; a one-Process Summary has no multi-Core Full stage.
- Full preserves nodes, edges, memberships, data-flow labels and legends. Geometry can change. Existing shared boundary Entities or declared inter-Core boundary edges must reproduce the Summary's Process relation graph.
- Function/Summary parent structure is enforced without adding a new Human-approval gate. Showing each stage for feedback is the authoring practice. Core approvals and a separate Full assembly decision are bound to exact file hashes. Simulated decisions require `simulation:true` and are reported as simulated evidence.
- Render adapters reuse the prior prebuilt runtime while source JSON and receipt stages retain canonical type names. Core/Full start folded; inter-Core data remains visible. Full alone has initial-input Hover tokens with changing artifact labels and immediate cancellation on new Hover. No normal Play/Stop buttons.
- CLI `version` reports `v3.9-cli`. The existing `v3_8_cli/` source path is retained for compatibility. The new package is `designing-relation-diagrams-v3.9-cli.skill`; the earlier package is preserved.

Existing files were patched at the relevant lines. New contract/validator/test files contain the new behavior rather than copying the whole source tree. Untyped and genuine legacy inputs remain compatible, but new `workflow_unit` metadata cannot disguise a legacy type as a canonical unit.
