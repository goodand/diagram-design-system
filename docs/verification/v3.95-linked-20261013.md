# v3.95 linked Full / fold-aware Hover verification

Author: chatgpt_gpt6
Date: 2026-10-13

## Problem and evidence

Hover must follow the currently represented Core scope when a parent Full expands a separately authored child Full. A shared detailed node activates a union; it must not accidentally activate its entire ancestor Core. Approved source files must retain their exact bytes.

The fail-first `test/linked-hover.test.mjs` reproduced both collapsed-detail and expanded-detail ancestor promotion before the runtime patch (2 failures). Local `scope`, `project`, `withAutoFolds`, and workflow reference validation were reused. No external implementation was necessary for this feature.

## Implementation

- Optional `linked_diagrams` on Process_Full binds a process to exact independent Function/Full references, a Human decision, and a directional boundary map.
- Composition creates a presentation clone. Canonical IR and approved snapshots remain unchanged. Child IDs are namespaced and collisions rejected.
- One external expansion depth. Child detail is flattened to its Core union; child Summary fold wrappers are not imported as another layer.
- Collapsed detail uses child membership union. Expanded detail suppresses only its own ancestor membership. Shared boundary peers remain eligible. All expand / All collapse reuse existing redraw and cancel tokens.
- CLI `verify` revalidates linked file hashes and approvals, not just generated files.

## Verification

- Focused unit tests cover union/exclusion, immutable sources, bad refs/boundaries/approvals, depth, simulated approvals, finite cycle animation, and CLI tamper detection.
- The final complete regression run passed 111/111 tests (including Core-internal target IDs and finite-loop animation). Final results are recorded in the local evidence folder.
- Main inspected source and rendered PNGs, rather than relying only on subagent reports.
- Headless Edge browser checks: default folded; root expanded/child folded; all expanded; unique/shared/boundary Hover; token start in folded and expanded states; new Hover cancels tokens; collapse cancels playback and clears focus; no browser exceptions. The same checks passed with optional libavoid routing enabled.
- Synthetic test decisions are simulated, not actual Human approvals. The browser experiment validates interactions, not a fresh agent's autonomous elicitation of Human feedback.

CLI PNG generation was disabled in this experiment; receipt S7 remains UNKNOWN. Separate Playwright screenshots were generated and read directly by Main.

Local reproducible artifacts: `outputs/dds-v3.95-linked/` in the task workspace. `check-browser.cjs`, screenshots, `browser-check.json`, and test logs are preserved there. `outputs/dds-v3.95-linked-build.mjs` constructs the synthetic fixture. Product decision JSON is local-only under the same output directory, consistent with the repository's upload exclusion policy.

## Limits

Linked layout is translated from its input anchor, not automatically repacked. Authors must reserve space and inspect the final expanded rendering. Optional v3.94 libavoid routing controls edge routes, not node placement. This implementation does not introduce recursive diagram types or arbitrary-depth expansion.

## Viewport correction

The original standalone SVG used the full browser width without a viewport height constraint: at 1280x720 the folded SVG bottom was 5117.67px. A fail-first browser assertion reproduced this. The HTML now uses a viewport-height flex layout, reserves the controls area, and fits the SVG to both available dimensions while preserving its aspect ratio. Fold redraws inherit the same CSS. Four viewport sizes (640x360 through 1920x1080), each folded and expanded, passed; existing Hover/token browser checks also passed. Main read the final expanded screenshot. Evidence: `check-viewport.cjs`, `viewport-check.json`, `viewport-folded.png`, `viewport-expanded.png` in the local experiment folder.
