선과 면

여러 가지로 표현될 수 있는 것을 식별력과 가독성이 높아지는 쪽으로 하나로 정하는 것 — 그것이 design system 을 세우는 일이다. 이 페이지는 docs/diagrams/digram_design.md(표현 규약 정본, 2026-09-12)를 적용해서 보인다. 위계는 Core → Main → Sub — 선의 Core 는 촉 유무 한 축, 면의 Core 는 직사각 / Stadium 한 축이고, 곡선/직선·실선/점선·채움은 Main 이다. 의미 넷(실행흐름 · 목적/수단 · is_a · 전체/부분)은 곡선 × 촉으로 갈리고, 전체/부분만 선을 떠나 영역으로 간다. 실선/점선은 의미가 아니라 확실성을 나르며 의미 축과 직교한다. 표현↔의미는 1:1 을 추구하되 강제하지 않는다 — 겹치면 우선순위로 푼다.

면 — Core 1축(직사각 / Stadium) · Main 1축(채움)

Core 는 축 하나다 — 모양: 직사각(하는 것 · Process) / Stadium(있는 것 · Entity). 가장 먼저 식별되는 축이라 Core 에 둔다. 채움은 한 단 내려 Main 이다 — 채움 = 구체(값이 있는 자료 · 코드가 있는 구현), 투명 = 추상(개념 · 과업). Sub 는 모서리 각(둥근/뾰족, 미사용). 아래 격자는 Core × Main 이고, 칸에 붙은 이름은 예시이지 고정값이 아니다(표현↔의미 1:1 은 추구하되 강제하지 않는다 — 겹치면 우선순위).

선 — Core 1축(촉 유무) · Main 2축(곡선/직선 × 실선/점선)

Core 는 축 하나다(2026-09-12 규약): 촉 유무 — 있으면 선이 방향을 나르고, 없으면 배치가 암시한다. 앞 판은 실선/점선을 Core 둘째 축으로 두었는데, 점선은 노드 외곽선·영역 경계에도 쓰여 한 자리에서만 뜻이 갈리지 않는다 — Core 에서 내렸다. Main 은 곡선/직선과 실선/점선 둘이고, 의미 넷은 곡선 × 촉으로 갈린다. 실선/점선은 의미가 아니라 확실성을 나른다(아래 셋째 그림, 의미 축과 직교).

의미 넷과 그 표현 — 무엇을 어디에 매핑했나 (표현 규약 2026-09-12)

사용자의 정식화: 「이것은 의미를 분류하고 그 의미에 어떤 표현을 매핑할 것인지 결정하는 의사결정이며 의사소통이다.」 의미 넷은 그대로다(실행흐름 · 목적/수단 · is_a · 전체/부분). 바뀐 것은 무엇으로 그리는가다 — 앞 판의 「수평/수직 × 실선/점선」이 「곡선/직선 × 촉 유무」로 바뀌었고, 전체/부분은 선을 떠나 영역이 됐다. 그래서 실선/점선이 통째로 비어 확실성을 나르게 됐다.

적용 1 — 파이프라인 한 조각, 이 열한 가지만으로

위에서 목적이 가는 점선으로 내려오고(C3), 왼쪽의 예시 자료(호박 원형, 값은 「개 is_a 갯과」)가 곡선으로 과업에 들어가 과업 사이를 점선 화살표로 흐르고(C2), 과업 아래로 실선이 핵심 구성에 닿는다(C4). 구현은 실선 — 저장소에 실제로 있는 물건이라서. is_a 는 여기 없다 — 파이프라인 도식에서 개념 관계는 자료의 값이고, 간선으로 그리는 것은 개념 그래프 계열(적용 2 · 대조 (4))의 몫이다. 그래서 예시(호박)와 개념(흰 원형)이 한눈에 갈린다.

적용 2 — 개념 그래프 한 조각: 등록부가 촉 모양을 정한다

이 그림은 노드마다 관계 하나씩을 한 장에 섞은 범례다(대조용은 아래 「의미별로 하나씩」). 여기서는 모든 간선이 C1(직·단·실)이고, 종류는 그림이 아니라 등록부 feature_type 이 촉 모양으로 나른다 — 분류는 빈 삼각, 부분–전체는 마름모, 구성원은 빈 마름모, 그 외는 보통 촉. 라벨이 정확한 종류다.

의미별로 하나씩 — 시각 대조를 위한 네 그래프 (각 그래프는 한 관계만)

사용자 요구(2026-09-07): 「(1) 실행흐름 (2) 전체/부분 (3) 목적/수단 (4) is_a 네 가지 모두 DAG 로도 표현할 수 있다는 것을 보여야 한다 — 각각을 적용한 사례를 포함시켜라 … 이런 것들이 필요한 것은 시각적인 대조를 확인하기 위함이다.」 위 「적용 2」는 노드마다 관계 하나씩을 한 그림에 섞은 범례였다. 여기서는 그래프마다 관계 하나만 그린다 — is_a 만 보이는 그래프, 전체/부분만 보이는 그래프 — 그래야 넷이 나란히 놓였을 때 표현이 서로 구별되는지 눈으로 확인된다. 넷 다 이 저장소의 실물이고, 출처는 캡션에. 나무는 DAG 의 특수한 경우이고, 부모를 공유하는 순간 그대로 DAG 다.

이 적용판이 말하지 않는 것

  • 직선 · 촉 없음 칸이 비어 있다. 보류된 「구현/구현체(instance)」 의미가 그 자리의 후보다 — 목적/수단에 넣을지 별도 Sub 로 둘지 미정(digram_design.md).
  • 등록부 렌더러가 이 규약보다 앞선다. l1_s5_model.edge_code 는 is_a 를 직선 + 빈 삼각으로 그린다(적용 2) — Sub 층이지만 손그림과 갈라져 있다.
  • 확실성 gradient 의 눈금이 규약에 없다. 이 페이지는 네 단(실선 · 7 3 · 7 7 · 7 13)을 썼지만 정본은 「좁을수록 확실」만 정한다.
  • 선의 Sub 축이 미정이다(정본 표의 빈칸). 면의 Sub(모서리 각)는 정해졌으나 아직 아무 의미도 싣지 않았다.
  • 이 페이지의 색은 정본이 아니다. 정본은 「특정 의미에 어떤 색·촉 모양·장식을 주는 규칙은 프롬프트에 없는 한 확정하지 않는다」고 명시한다 — 자두(목적)·청록(영역)·호박(자료)은 이 페이지의 지역 선택이다.
  • 해석 우선순위: ① 사용자의 현재 프롬프트 → ② digram_design.md → ③ 이 적용판의 시각적 구현. 여기서 확정된 것처럼 보이는 세부 표현은 정본이 아니다.
  • 노드의 동일성(같은 이름 = 같은 노드?)과 자료의 출처(실측인지 예시인지)는 여전히 표시가 없다.
